# Пример автотестов REST API Яндекс Диска

Небольшой проект на Java 17, JUnit 5 и Maven. Он проверяет HTTP-методы `GET`, `POST`, `PUT` и `DELETE` для ресурсов Яндекс Диска. По умолчанию тесты обращаются только к локальному HTTP-серверу и не требуют OAuth-токена. Шесть интеграционных тестов можно запустить против `https://cloud-api.yandex.net` с токеном **выделенной тестовой учётной записи**.

## Что проверяется

| Метод | Запрос | Локальная проверка | Реальный API |
| --- | --- | --- | --- |
| GET | `/v1/disk/resources?path=...` | URL, OAuth-заголовок, ответ 200 | Метаданные созданной папки |
| PUT | `/v1/disk/resources?path=...` | URL, ответ 201 | Создание двух папок |
| POST | `/v1/disk/resources/copy?from=...&path=...` | Оба параметра, ответ 201 | Копирование пустой папки |
| DELETE | `/v1/disk/resources?path=...&permanently=true` | Путь и флаг, ответ 204 | Удаление копии и очистка папки теста |

Локальные тесты проверяют формирование запросов клиента, а не поведение сервиса Яндекса. Реальный тест проверяет последовательность операций и допускает асинхронный ответ `202` для копирования и удаления.

### Дополнительные сценарии

| Проверка | Ожидаемый результат |
| --- | --- |
| GET с заведомо неверным OAuth-токеном | HTTP 401 и непустое поле `error` в JSON |
| GET отсутствующего ресурса | HTTP 404 и JSON-ошибка |
| DELETE отсутствующего ресурса | HTTP 404 и JSON-ошибка |
| PUT папки по уже существующему пути | HTTP 409; исходная папка по-прежнему доступна через GET |
| POST копирования отсутствующего источника | HTTP 404; целевой ресурс не создан |
| POST с кириллицей и символами `+ & # % ? =` в обоих путях | Локальный сервер получает исходные строки без потери символов и лишних query-параметров |

Интеграционные тесты независимы. Сценарии, создающие ресурсы, используют собственные папки с UUID; `@AfterEach` удаляет папку и проверяет HTTP 404, в том числе после падения теста.

## Запуск

Нужны JDK 17+ и Maven 3.9+.

```bash
mvn test
```

Ожидаемый результат по умолчанию: пять локальных тестов проходят; шесть тестов `DiskApiLiveTest` пропускаются. Этот же набор запускается в GitHub Actions на каждом push и pull request.

### Проверка реального Диска

Получите OAuth-токен **для отдельной тестовой учётной записи** с правом работы с её Диском. Не используйте личную учётную запись. Передайте токен через переменную окружения `YANDEX_DISK_TOKEN`, затем включите живой тест:

```bash
printf 'OAuth token: '
read -s YANDEX_DISK_TOKEN
printf '\n'
export YANDEX_DISK_TOKEN
export YANDEX_DISK_RUN_LIVE=true
mvn test
unset YANDEX_DISK_TOKEN YANDEX_DISK_RUN_LIVE
```

Токен не нужен для GitHub Actions и не должен попадать в репозиторий, логи или командную историю. Тесты, создающие ресурсы, используют уникальную папку `disk:/yandex-disk-api-tests-<UUID>`; после проверки она удаляется в `@AfterEach`, а тест дожидается ответа `404` на запрос её метаданных. `DELETE` с `permanently=true` удаляет её без корзины, поэтому запускайте тесты только на выделенном тестовом Диске.

## Проверенный прогон

26 сентября 2026 года выполнен локальный прогон против реального `https://cloud-api.yandex.net` с токеном отдельной тестовой учётной записи: **5 тестов, 0 ошибок, 0 пропусков**. Живой сценарий проверил GET, PUT, POST и DELETE, включая подтверждение удаления временной папки. [Результаты и проверенная версия исходников](docs/live-api-verification.md).

GitHub Actions по-прежнему запускает локальные HTTP-тесты без OAuth-токена; живой сценарий включается вручную.

## Структура

- `src/main/java/.../DiskApiClient.java` — минимальный HTTP-клиент на стандартном `java.net.http`.
- `src/test/java/.../DiskApiClientTest.java` — пять локальных тестов с HTTP-сервером JDK.
- `src/test/java/.../DiskApiLiveTest.java` — шесть включаемых вручную тестов реального API.
- `.github/workflows/tests.yml` — CI без токена.
